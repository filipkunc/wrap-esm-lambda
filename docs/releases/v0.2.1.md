# v0.2.1 — the practical composition, proven on the platform's own image

No changes to the published packages. This release is the answer to "what
does it look like to actually use this on Lambda" — a runnable example
composing everything the toolkit does, tested through AWS's real runtime
interface client on the real runtime images, with the platform's own
accounting read back off the logs.

## Highlights

- **One config, both Lambda shapes, zero app changes.**
  [`examples/hono-lambda`](../../examples/hono-lambda) is an ordinary
  [Hono](https://hono.dev/) app behind `hono/aws-lambda`'s `handle()` and
  an ordinary SQS consumer next to it — neither imports the toolkit. The
  same `wrap.config.mjs` instruments three layers of each: the handler
  itself (discovered from `_HANDLER` at preload by the aws-lambda preset,
  timed per invocation with wall time and RSS), the framework (`Hono`
  rebound to a subclass that logs the matched route **template** — OTel's
  `http.route` — its class-field entry points being invisible to prototype
  patching), and the AWS SDK beneath (every `@aws-sdk/client-*` operation
  funnels through `Client#send` in `@smithy/core`; one entry sees S3's
  `PutObjectCommand` and SNS's `PublishCommand` alike).
- **SQS in, SNS out.** The consumer takes an SQS batch, publishes each
  parseable record to SNS, and returns the partial-batch contract —
  `batchItemFailures` names the records to redrive, exercised by a
  deliberately malformed fixture record. `_HANDLER=consumer.handler` is
  the only thing that differs from the HTTP handler's run.
- **No LocalStack, by construction.** The `Client#send` interception
  happens before the middleware stack builds — no credential resolution,
  no network — so the tests assert "what the app asked the SDK to do"
  with nothing to emulate, license, or keep compatible. A forwarding APM
  patch would use the identical interception point.
- **The platform's accounting, on the job summary.** The CI Lambda lane
  answers real API Gateway and SQS events through the runtime interface
  emulator the base images ship, and reads back three views per
  invocation: the REPORT line (real duration and billed milliseconds —
  the emulator's `Max Memory Used` merely echoes the configured size; it
  meters time, not memory), the container's cgroup peak (the genuine
  max-memory number an actual Lambda would have reported), and the
  patch's in-process wall time and RSS.

## Compatibility

Package surfaces, the engine contract and the config format are unchanged
from 0.2.0; this tag exists to version the example, the specs and the
