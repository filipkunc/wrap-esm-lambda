# v0.2.2 — the delivery contrast, billed and charted

No changes to the published packages. This release completes the
hono-lambda example's story with the question v0.2.1 left open: what does
runtime delivery actually cost against the same patches baked in at build
time — answered by the platform's own accounting, and charted where people
look.

## Highlights

- **Build-time delivery joins the example.** `build.mjs` bundles both
  handlers (the Hono HTTP app and the SQS→SNS consumer) with the
  unplugin's esbuild adapter and
  [`wrap.config.build.mjs`](../../examples/hono-lambda/wrap.config.build.mjs) —
  the runtime config's package entries reused verbatim, plus the handler
  entries written down explicitly, because a build machine has no
  `_HANDLER` to discover them from. The `dist/` output runs on plain node:
  no hook, no config, no engine in the process, and the outputs match the
  runtime legs line for line.
- **The contrast, billed by the platform.** The CI Lambda lane boots the
  bundle in a third container with nothing but `LAMBDA_TASK_ROOT` set and
  puts the two deliveries' cold starts side by side, straight off the
  REPORT line. The committed reference measurement
  ([`coldStartTable.md`](../../examples/hono-lambda/coldStartTable.md),
  five emulator boots per delivery): **runtime hook 269 ms / 91 MB RSS vs
  esbuild bundle 166 ms / 68 MB RSS** — the difference is the preload, the
  config evaluation, the engine binding and the on-load transforms, none
  of which exist in the bundle.
- **Charts where people look.** The reference measurement renders to
  `coldStartChart.svg` (chart.js, the `hooks/` charts' style) — embedded
  in the example README, on every Lambda lane's job summary next to that
  run's live numbers, PATCHed onto each same-repo PR as a sticky
  cold-start comment, and attached to this release. Release pages
  (starting with this one) embed all four benchmark charts inline via
  tag-pinned raw URLs instead of only listing them as assets. Mermaid was
  tried and rejected: GitHub parks its pan/zoom controls exactly on the
  bar being read, and labels no values.

## Compatibility

Package surfaces, the engine contract and the config format are unchanged
from 0.2.1.
