# v0.4.0 — native transforms behind a stable package boundary

This release moves the OXC addon to `@wrap-esm-lambda/engine-oxc`, makes the
two engines parallel packages, and keeps existing consumers safe with a
`wrap-esm-lambda` compatibility package.

## Package compatibility

The old unscoped package name is still published at the same version. It
depends on the scoped addon and forwards its complete CommonJS module object
and TypeScript declarations:

```js
require('wrap-esm-lambda') === require('@wrap-esm-lambda/engine-oxc')
```

Existing dependencies and imports continue to work. New code should use
`@wrap-esm-lambda/engine-oxc`; migration can happen independently of this
release. The pkg.pr.new tutorials install both names and CI asserts this
contract against the freshly published preview before running the runtime and
unplugin examples.

## Transform boundary

OXC now owns complete operations that benefit from native parsing: TypeScript
lowering, binding rewrites, source-map composition and recursive `export *`
resolution cross NAPI once. The Acorn engine stays a small pure-JavaScript
alternative and uses Node's position-preserving type stripping for erasable
TypeScript syntax.

The engine contract stays coarse and shared. Core loads
`@wrap-esm-lambda/engine-acorn` and `@wrap-esm-lambda/engine-oxc` through the
same surface, while runtime hooks and the unplugin continue to consume the same
configuration.
