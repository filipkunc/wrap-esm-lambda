# v0.3.0 — contracts enforced, dead surface retired

A hardening release: the places where the two engines and the two shells
were contracted to agree by comment now agree by shared code or by test,
two error paths stopped hiding what they knew, and public API nothing used
is gone. The minor bump is for the removals; runtime behavior of every
kept surface is unchanged.

## Breaking: two removals from `@wrap-esm-lambda/core`

- **`createMatcher`** returned only the first matching entry and was
  superseded when multi-entry matching landed; its last callers anywhere
  were its own tests. Migrate to `matchEntries(config, idOrUrl)` — take
  `[0]` if the old first-match behavior is genuinely what you want.
- **`SelectEngineOptions.defaultEngine`** had no caller. The default engine
  is `oxc`, and `WRAP_ESM_LAMBDA_ENGINE` remains the one lever over the
  binding.

Also gone, though nothing outside the repo could reach them: `toPath`
(never in core's exports map) and three engine-acorn helpers that were
exported but only ever used inside their own files.

## Contracts that were comments are now code or tests

- **The missing-export error is pinned.** Core's star-graph retry fires on
  the `export '<name>' not found in module` error, which the native engine
  (`src/transform/rewrite.rs`) and the acorn engine (`tap.mts`) each
  produce. The consumer-side match now lives in one exported predicate,
  `isMissingExportError`, and the engine-parity suite feeds both engines'
  actual error objects through it — rewording either producer fails a test
  instead of silently disabling star resolution.
- **The builtin accessor contract is shared code.** The build shell's
  generated wrapper and the runtime shell's `applyBuiltinPatches` are
  documented as mirroring each other exactly; they now share the binding
  validation (`assertBuiltinBinding`, with the version-drift error written
  once) and the runtime accessor construction is exported as
  `builtinAccessors`.

## Errors that said less than they knew

- **A malformed `upstreamMap` no longer panics the addon** — `exportsTap`
  reports it as an ordinary catchable error naming the bad input.
- **`validateConfig` surfaces star ambiguity.** A binding provided by
  several bare `export *` sources with different origins used to validate
  as merely "not exported"; the report now carries the walk's own refusal —
  which sources, which origins — the same error the tap raises at load
  time. Surfacing that ahead of time is the validator's whole purpose.
- The star walk traces unreadable/unparseable star sources under
  `WRAP_ESM_LAMBDA_DEBUG` rather than silently scoring them as "provides
  nothing".

## Internal

The Rust transform is split along its phases (export indexing, rewrite,
snippet emission, source-map chaining), the azure-functions preset along
its seams (platform contract, state model, timing, bracket, lifecycle),
and core's two nearest-package.json walks are one parameterized walk. None
of this moves a public surface; the parity suite and the full matrix ran
green on both engines throughout.

## Compatibility

Aside from the two removals above, package surfaces, the engine contract
(`TAP_CONTRACT_VERSION` stays 2 — emitted snippets are byte-identical) and
the config format are unchanged from 0.2.3.
